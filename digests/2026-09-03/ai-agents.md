## 7️⃣ 用户反馈摘要  

- **实时语音会话泄漏**（#116201）被多位运营者报告为导致节点 CPU 与内存飙升，尤其在网络抖动时最为明显。  
- **子代理结果不可见**（#44925、#67777）导致业务流程卡死，用户希望 **明确告警** 与 **手动重试** 按钮。  
- **长对话/工具调用后参数丢失**（#53408）让用户在自动化脚本中出现空指令，呼吁 **持久化 session context**。  
- **跨渠道媒体不统一**（#110346、#120735）对 WhatsApp 与 Telegram 的媒体路径差异产生困惑，要求统一 `local-media-allowlist`。  
- **Cron 任务导致事件循环饱和**（#84983）在生产环境中造成数分钟的服务不可用，用户期望 **背压 & 限流**。  
- **插件 UI 交互失效**（#136433、#136440）在 Tab/图片 hover 时出现交互丢失，提示 UI 测试覆盖不足。  

> **共性痛点**：**可靠性（不丢失、不卡死）**、**统一的跨渠道媒体处理**、**可观测的错误与告警**，以及 **资源/费用管理**。

OpenClaw 今日保持 **高活跃度** 与 **快速迭代**，但 **核心可靠性（P0/P1 崩溃、子代理结果丢失）** 仍是最紧迫的技术债务。已合并的几项关键 PR 为网关状态管理、子代理超时区分以及 UI/CLI 安全性提供了重要支撑。后续两周内建议：

持续关注上述积压议题，将有助于提升 OpenClaw 在 **企业级可靠性** 与 **多模态生态** 的竞争力。
